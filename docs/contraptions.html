Contraption System

Moving structures captured into an isolated sub-level with XPBD physics, bearings, vehicle control, and entity culling.

What Is a Contraption?

A contraption is a set of blocks captured from the world and moved as a rigid unit. The blocks live in an isolated ContraptionLevel (a custom NMS Level subclass) and are rendered to players as a collection of display entities - one per block. Physical interactions with the contraption happen through collision detection against the display entities' hitboxes.

Lifecycle

  1. Assembly - A bearing block (piston bearing, rotational bearing, minecart bearing, ghast harness) is powered. ContraptionAssembler BFS-flood-fills connected blocks into a block list.
  2. Capture - Captured blocks are removed from the world and stored in the contraption level. Display entities are spawned at the bearing position.
  3. Motion - Each tick, the physics solver (XPBD) advances the contraption's pose. Display entities receive teleport packets to match.
  4. Disassembly - The bearing is depowered or the contraption is killed. Blocks are placed back into the world.

Bearing Types

Piston BearingPistonBearingBehaviorLinear extension/retraction. Powered by redstone; stroke length is configurable.

contraptions.yml Reference

The main config file lives at plugins/CraftEnginePolyfills/contraptions.yml.

Entity Culling

entity_culling:
  # Master toggle. Disable to send all element packets to every player (legacy).
  enabled: true

  # Maximum distance (blocks) from the bearing at which display entities
  # are sent. Players beyond this distance receive despawn packets.
  view_distance: 64.0

  frustum:
    # Enable directional frustum culling.
    enabled: false

    # Total field-of-view cone in degrees.
    fov: 120.0

    # Distance within which frustum culling is bypassed (always show).
    near_bypass: 16.0

    # Expand the target sphere by this many blocks for the frustum check.
    # Compensates for large contraptions whose parts extend beyond the centre.
    expansion: 8.0

Physics Model

Contraptions use an XPBD (Extended Position-Based Dynamics) solver with four material axes:

FilePropertyDescription
mass.ymlMass per block typeHeavier blocks require more force to accelerate. Defaults loaded from plugin; overrides per block material.
friction.ymlFriction per block typeSurface friction used in sliding contact resolution.
restitution.ymlRestitution per block typeBounciness (0 = fully inelastic, 1 = fully elastic).
floatability.ymlFloatability per block typeWhether the block contributes buoyancy when submerged.

Vehicle Control

Vehicle-capable contraptions use the VehicleControlBehavior. Seats are defined in vehicle-seats.yml. Players riding a contraption send directional input through VehicleDriverRegistry, which translates it into force vectors applied by the physics solver.

Performance Notes

  • Enable entity_culling - this is the single biggest client-side optimization. Set view_distance to match your server's render distance.
  • Enable frustum culling for servers with many players viewing large contraptions simultaneously.
  • Keep contraptions under ~500 blocks for stable physics ticks (16ms budget).
  • Avoid simulate_flow: true unless the contraption intentionally contains flowing fluid - it adds a fluid BFS each tick.
