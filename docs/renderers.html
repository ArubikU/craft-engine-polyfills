Renderer System

Formula-driven visual layer for machines — BetterModel, displays, particles, sounds, and more.

Overview

Every machine definition can declare a "renderers" array. Each entry is a RendererSpec — a sealed record that describes one visual element. The RendererManager evaluates them each tick using the machine's live PolyContext.

All numeric fields accept PolyFormula expressions, variable references ("$name"), or bare literals. All renderer specs share three common fields:

Common FieldTypeDefaultDescription
whenStr"always"PolyFormula condition. Renderer is active while this evaluates to truthy.
update_whenStr"always""always" | "inventory" | "state" | "processing" | "never". Controls re-evaluation frequency.
runStrnullName of a .pf script to evaluate before this renderer. Variables defined in the script are injected into the context.

Position Resolution

All position-bearing specs use a "location" field that accepts several formats:

FormatExampleBehavior
Array[3] of numbers[0.5, 1.2, 0.5]Relative offset added to machine block centre (x+0.5, y, z+0.5).
Object with x/y/z keys{"x": 0.5, "y": "rpm * 0.01", "z": 0}Per-axis expressions, evaluated each tick. Relative offset.
String expression"Machine.location"Evaluates to Obj(LocationClass) — treated as absolute world coordinates.
null / omitted—Renders at machine block centre.

The "positions" (or "locations") key accepts an expression returning an Array of location values, firing the renderer once per resolved position.

BetterModel Renderer

{
  "type": "bettermodel",
  "model_id": "crusher",
  "animation": "on",
  "speed": "max(0.05, overclock)",
  "when": "processing && rpm > 0",
  "run": "crusher"
}
FieldTypeDefaultDescription
typeStr—Must be "bettermodel".
model_idStrRequiredBetterModel blueprint ID (registered in BetterModel's resource system).
animationStrnullAnimation name to loop while active. Null = idle pose only.
speedExpr"1.0"Animation playback speed multiplier expression. 1.0 = normal speed.
whenExpr"always"Condition to activate this renderer.
runStrnull.pf script reference (script base-name without extension).
NoteBetterModel must be installed. The renderer gracefully no-ops if BetterModel is absent.

Multi-Position (PositionedSpec Wrapper)

Any renderer spec can be wrapped with a "positions" field to fire it once per resolved position:

{
  "type": "particle",
  "particle": "FLAME",
  "count": "1",
  "positions": "World.entities(Machine.x, Machine.y, Machine.z, 4).map_prop('location')",
  "when": "processing"
}

The "positions" value is a PolyFormula expression that must evaluate to an Array of location values (Obj(LocationClass) or Array[3] of relative numbers). The renderer fires once per element.

Declaring Variables

Variables in the machine JSON "variables" block are evaluated once per tick before renderers run and their results are injected into all renderer contexts:

"variables": {
  "running":    "processing && rpm > 0",
  "speed_mult": "max(0.05, overclock)",
  "smoke_count": "running ? clamp(floor(rpm / 10), 1, 6) : 0"
}

In renderer specs, reference them as "$running" (with dollar sign) or as bare "running" in expressions.

RendererManager

The RendererManager class manages all renderer instances for one machine block entity. It is created in DataMachineBlockEntity when the definition has renderers, and ticked each game tick to update all active display entities.

MethodDescription
tick(context)Evaluate all renderer specs against the context and update display entities.
destroy()Remove all spawned display entities from the world.
snapshot()Capture evaluated item display states for contraption rendering.
