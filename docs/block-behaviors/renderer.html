polyfills:renderer

Attaches the PolyFormula renderer system (particles, text displays, item displays, BetterModel, ModelEngine) to any CE custom block - no full machine infrastructure required.

Java class: dev.arubik.craftengine.block.behavior.RendererBehavior
Registered as: BlockBehaviors.POLYFILL_RENDERER
Block entity: none - driven entirely by the block's random tick
Related docs: Renderer System · PolyFormula Engine

Description

On every block tick the behavior reads the block's current redstone level (0–15), its facing property (if present), and any container inventory attached to the block entity (chest, barrel, hopper, dispenser). It then evaluates the configured variables using PolyFormula and drives each renderer spec: spawning particles, updating display entities, or controlling BetterModel/ModelEngine animations.

This is the lightweight path when you need visual effects on a plain custom block. For a full machine with a GUI, recipe processing, and upgrade slots, use polyfills:data_machine instead - it uses the same renderer infrastructure internally.

Ticking required The block must have randomTick or tick enabled in the CE block YAML for renderers to fire. Add settings.tick: true to your block definition.

Configuration

KeyTypeDefaultDescription
variablesMap<String, String>{}Named PolyFormula expressions. Values are evaluated each tick and available to when, update_when, and inline fields in each renderer spec. Example: powered: "redstone > 0".
renderersList<Map>[]Ordered list of renderer spec objects. See renderer types below.

Renderer spec common fields

KeyTypeDefaultDescription
typeStringparticleOne of: particle, text_display, item_display, bettermodel, modelengine.
whenPolyExpralwaysCondition controlling whether this renderer is active. Evaluated as a boolean (empty string / "always" = always active).
update_whenPolyExpralwaysCondition controlling whether the renderer is updated this tick (useful to throttle expensive updates).
runPolyScript idnullOptional PolyScript to execute when the renderer fires.
location / offset_x/y/zPolyExpr / float0.5,0.5,0.5Position offset from block origin. Can be a 3-element list expression or separate offset_x, offset_y, offset_z keys.

Example

blocks:
  cml:signal_lamp:
    settings:
      tick: true
    states:
      state: "minecraft:amethyst_block"
    behavior:
      type: polyfills:renderer
      variables:
        powered: "redstone > 0"
      renderers:
        - type: particle
          particle: FLAME
          offset_y: "0.9"
          count: "redstone / 4"
          when: powered
          interval: 2
        - type: text_display
          text: "'Signal: ' + redstone"
          offset_y: "1.5"
          billboard: center
          scale: "0.08"
          when: powered
          update_when: powered

Implementation Notes

The behavior resolves the block's redstone level with ServerLevel.getBestNeighborSignal() each tick. If the block also has a block entity that implements net.minecraft.world.Container, its inventory is exposed to PolyFormula via the inventory context object.

The RendererManager instance is created lazily on first tick and reused across subsequent ticks. Changes to the behavior's config section at reload time recreate the behavior instance and thus the manager.
