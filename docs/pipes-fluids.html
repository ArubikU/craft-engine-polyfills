Pipes, Fluids & Gas

Graph-solved pressure networks: pipe types, fluid types, gas types, tanks, valves, and pumps.

Network Architecture

The fluid and gas network is modeled as a graph where:

  • Nodes are tanks, machines with tanks, valves, and pumps.
  • Edges are pipe connections between adjacent nodes.
  • Each tick, the FluidNetworkSolver runs a pressure-based flow algorithm — fluid flows from high-pressure nodes to low-pressure nodes along edges, up to each edge's transfer_per_tick capacity.

Gas networks use the same graph structure and solver as fluid networks.

Pipe types are defined in plugins/CraftEnginePolyfills/pipe_types/*.json.

Gas Types

Gas types are defined in plugins/CraftEnginePolyfills/gas_types/*.json. Same format as fluid types with identical fields. Gases use a separate solver but the same graph structure.

Fluid Interactions

Fluid interactions define how a player with a bucket or bottle interacts with a fluid carrier block. They live in plugins/CraftEnginePolyfills/fluid_interactions/*.json.

{
  "type": "fill",
  "fluid": "polyfills:water",
  "item_in":  "minecraft:water_bucket",
  "item_out": "minecraft:bucket",
  "amount":   1000
}
KeyDescription
type"fill" — player adds fluid to the carrier. "drain" — player takes fluid from the carrier.
fluidFluid type being transferred.
item_inItem the player must be holding.
item_outItem returned to the player after the interaction.
amountmB transferred.

Pumps

Pump definitions live in plugins/CraftEnginePolyfills/pumps/*.json. A pump is a machine that actively moves fluid from a source to a destination against gravity using fuel.

{
  "id": "polyfills:machine_pump",
  "block": "cml:machine_pump",
  "fuel_type": "machine_pump",
  "max_height": 16,
  "collect_radius": 1
}

Network Solver

public class FluidNetworkSolver // package: dev.arubik.craftengine.fluid.graph

Solves one fluid network graph per tick using a pressure-gradient algorithm. The solver:

  1. Assigns a pressure value to each node based on its fill level and height (density × height × gravity).
  2. For each edge (pipe), computes flow = conductance × Δpressure, clamped to transfer_per_tick.
  3. Applies flows atomically to avoid oscillation.
