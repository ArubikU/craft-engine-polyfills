PolyFormula Engine

Typed expression engine used by machine renderers, variable declarations, and .pf scripts.

Overview

PolyFormula is a compile-once, evaluate-many expression engine. Expressions are compiled once at load time to an AST and evaluated each tick against a PolyContext containing the machine state, inventory, tanks, and other domain objects.

// Compile once
PolyFormula f = PolyFormula.compile("is_empty(slot(0)) || rpm > 200");

// Evaluate each tick
boolean active = f.evaluateBool(ctx);
double  speed  = PolyFormula.compile("max(0.05, overclock)").evaluateNum(ctx);
String  label  = PolyFormula.compile("format('%d%%', floor(progress/max_progress*100))").evaluateStr(ctx);

Grammar

Operator precedence, lowest to highest:

ternary   →  condition ? trueVal : falseVal
or        →  a || b
and       →  a && b
not       →  !a
compare   →  a == b  |  a != b  |  a < b  |  a <= b  |  a > b  |  a >= b
coalesce  →  a ?? b          (returns a unless a is null/AIR-item)
add       →  a + b  |  a - b
mul       →  a * b  |  a / b  |  a % b
pow       →  a ^ b           (right-associative)
unary     →  -a
primary   →  NUMBER | STRING | $name | name | name.prop | name.method(args)
          |  ClassName.prop | ClassName.method(args) | (expr)

Literals

  • Number: 42, 3.14, 1e6, .5
  • String: "text" or 'text' with \n \t \r \\ escapes
  • Boolean: true / false (or TRUE / FALSE)
  • Constants: PI, TAU, E, INF, NAN
  • Variables: $name or bare name — looked up in the current PolyContext

PolyScript (.pf files)

A .pf file is a script that defines named variables available to all renderer specs that declare "run": "scriptname". The script is evaluated sequentially before rendering; later assignments can reference earlier ones.

# crusher.pf — renderer script for the crusher machine
# Variables here are available to all renderers that declare "run": "crusher"

# Simple assignment
speed_mult  = max(0.05, overclock)
running     = processing && rpm > 0

# Particle intensity scales with rpm
smoke_count = running ? clamp(floor(rpm / 10), 1, 6) : 0

# Vertical pulse via trig
pulse_y = max_progress > 0 ? sin(progress / max_progress * TAU) * 0.1 : 0

# If / else if / else
if running && overclock > 2.5 {
    glow = true
    turbo = true
} else if running {
    glow = false
    turbo = false
} else {
    glow = false
    turbo = false
}

# For loop — iterate over upgrade items
upgrade_bonus = 0
for item in Upgrades.inventory {
    upgrade_bonus = upgrade_bonus + item_count(item)
}

Script Format

  • Lines starting with # are comments.
  • Assignments: name = expr
  • If/else: if condition { … } else if … { … } else { … } — opening brace on same line as condition.
  • For: for varName in iterExpr { … } — binds each element as varName (also e / element).
  • Variables written inside a branch or loop are visible to subsequent statements.

Practical Examples

# Show BetterModel animation only while running and powered
"when": "processing && rpm > 0"

# Scale animation speed to overclock (min 5% to prevent freeze)
"speed": "max(0.05, overclock)"

# Particle count scales with RPM, capped at 6
"count": "running ? clamp(floor(rpm / 10), 1, 6) : 0"

# Text display showing fluid fill percent
"text": "format('Water: %d%%', floor(FluidTank('water', 'percent')))"

# Rotate item display to face nearest player (look-at billboard)
"rot_y": "Machine.nearest_player_yaw"

# Animated bounce: full sine wave per progress cycle
"location": [0.5, "1.0 + sin(progress / max_progress * TAU) * 0.15", 0.5]

# Conditional particle only when overclock is high
"when": "processing && overclock > 1.5"

# Use CE item in renderer
"item": "CraftEngineItem('cml:upgrade_diamond')"
